# EvolutionSandbox 后续开发计划

更新时间：2026-07-24

当前基线：v0.5.0 + 本地未发布开发切片

状态：持续更新；以代码、测试与 `CHANGELOG.md` 的当前事实为准

## 1. 当前基础

v0.5.0 已经具备以下可复用基础：

- 浏览器与 Luanti 共用确定性内容包和原点演化规则；
- 浏览器动漫风 WebGL 3D 演示、即时行为反馈与演化消息序列；
- ESIP 0.1 消息外壳、schema、能力声明、revision、序列和幂等控制；
- 真实 Luanti bridge 与认证回环 HTTP sidecar；
- 不透明 actor 身份映射、多人世界时间线注册表和增量追赶；
- 浏览器持久存档、Luanti metadata/mod storage 存档和旧版本迁移；
- 自动测试、公开树检查、Pages 在线演示和版本 Release 流程。
- journal/checkpoint 持久 SidecarStore、重启恢复、诊断接口与损坏失败关闭；
- 确定性文明内核、时间线分支、ESIP 文明适配器与三个原创预设；
- 独立恒星生命周期内核和默认不进入公开构建的 Babylon 星辰实验页；
- 本地确定性 AI 导演、可恢复审批闸门和隔离的实验网页入口；
- 受控场景流、一次性转场许可和从原点接力到星辰的全自动演化自检。
- `WorldObservation v0` 严格公共外壳、三个领域只读适配器和统一观察注册表。
- 默认不进入公开构建、只消费公共观察的 Babylon 文明观测台。
- `WorldExperimentProposal v0`、五类受限文明 Rule Patch、二次确认和可验证分支因果链。
- openVirFactory 独立模型工具、固定 pending 回环响应和 EvolutionSandbox 只读复核适配器。
- 文明 sidecar runtime、原子 controller checkpoint、时间槽 pulse 调度、租约恢复与确认丢失去重。
- 正式文明实验 ESIP 评审/提交消息、严格 source/actor/universe 绑定、请求过期和跨重启提交幂等。

原路线中的通用持久 SidecarStore 缺口已经由未发布开发切片补齐。`WorldObservation v0`、Babylon 文明观测台、`WorldExperimentProposal v0` 和 openVirFactory pending 适配已经证明：应用可以先只读观察，模型只生成受限候选，再经二次确认建立带来源、hash、Rule Patch 和 revision 的差异分支。相同的持久恢复与租约语义现已应用到文明 controller 调度，正式实验消息也已固定评审与提交边界；下一阶段应实现同源身份网关和 provider 验收，而不是扩大 AI 权限。

## 2. 开发原则

后续版本继续遵守以下边界：

1. 游戏状态只能由明确的权威平台写入，AI、网页和传输层不能直接改数据库。
2. 跨平台只交换结构化业务事实，不同步渲染帧、引擎对象或任意代码。
3. 所有存档语义变更必须提供版本号、迁移路径和损坏时的失败关闭行为。
4. 新命令默认拒绝，必须同时补齐 schema、运行时验证、授权、幂等和测试。
5. 浏览器在线演示保持自包含，不依赖第三方 CDN、远程模型或公开 sidecar。
6. 界面动画只呈现已经确认的状态；关闭 WebGL 后，规则闭环仍必须可用。
7. 每个发布版本都必须通过 `npm run verify`，高风险版本还要完成真实 Luanti 往返测试。

## 4. v0.6.0：持久事件传输

实现状态：本地未发布切片已经完成本节主要交付项和自动测试；发布前仍需版本整理与真实运行时复核。

### 目标

让 sidecar 在正常重启和意外中断后恢复未完成命令、结果 cursor、来源 sequence、租约和去重状态，避免重复执行权威行为。

### 交付项

- 定义 `SidecarStore` 接口，保留现有内存实现用于测试；
- 在 Git 忽略的 runtime 目录中增加持久 journal/checkpoint 实现；
- 持久化命令正文指纹、状态、租约、尝试次数和完成结果；
- 持久化每个 source 的最新 sequence 与单调结果 cursor；
- 启动时回收过期租约并恢复未完成命令；
- 增加可配置保留期、容量上限、压缩和安全删除；
- CLI 增加事件追赶、存储状态与只读诊断命令；
- 明确存储 schema 版本、升级流程和损坏时的恢复说明。

### 验收条件

- 在领取前、领取后和权威端执行后三个中断点重启，状态都能正确恢复；
- 重投相同 `source + id + 内容` 不重复改变玩家状态；
- 重用 ID 提交不同内容继续返回 `id_conflict`；
- cursor 和 sequence 在重启后保持单调；
- 损坏或不兼容的持久记录不会被静默清空；
- 内存模式、持久模式和真实 Luanti 往返测试全部通过。

## 5. v0.7.0：openVirFactory AI 导演

实现状态：确定性假导演、ESIP 适配器、可恢复人工审批、受控场景许可、全自动固定自检、`WorldObservation v0`、Babylon 文明观测台、`WorldExperimentProposal v0`、openVirFactory 模型提案适配和正式文明实验 ESIP 消息已完成；真实 provider 往返手工验收与同源身份网关尚未完成。

### 目标

让 AI 承担叙事导演、NPC 调度和受限建造建议，但不获得修改核心数值、存档或执行任意 Lua 的权限。

### 交付项

- 定义导演意图消息，例如叙事提示、允许行为建议、NPC 任务和白名单建造请求；
- 扩展 openVirFactory 适配器：文明实验保持待确认提案；导演、NPC 或建造输出只能转换为逐项验证并经过独立授权的 ESIP 意图；
- 为 source、actor、timeline、领域、节点前缀、坐标范围和速率分别授权；
- 把 correlation ID、模型请求摘要、决策结果和拒绝原因写入审计事件；
- 提供不调用外部模型的确定性假导演，保证离线测试可重复；
- 浏览器演示只回放公开导演事件，不嵌入密钥或直连模型供应商。

### 验收条件

- AI 无法绕过 `evolution_core` 和 openVirFactory 的结构化白名单；
- 同一导演意图重投不会重复放置节点或执行行为；
- 模型超时、无效 JSON、越权坐标和未知意图均安全失败；
- 关闭 AI 后，原有浏览器和 Luanti 小闭环继续独立运行。

## 6. v0.8.0：时间线世界语义

### 目标

把当前“切换玩家 timeline 上下文”扩展为可验证的世界分支，而不是复制整个世界数据库。

### 设计方向

- 优先采用同一 Luanti 世界中的隔离领域实例，为每条时间线分配确定性区域和入口；
- 时间线记录父分支、创建 revision、领域模板、创建者和成员关系；
- 地图、物品、玩家数值和共享资源分别定义归属，禁止隐式跨线复制；
- 分支创建采用准备、生成、确认流程；失败时不得留下半注册时间线；
- 为现有 registry schema 1 提供显式迁移。

### 验收条件

- 两名玩家可创建、加入并重新连接到不同领域实例；
- 时间线区域不会互相覆盖，入口与回程位置可恢复；
- 创建失败、服务器重启和重复命令不会产生孤立领域；
- 浏览器平台能用简化的领域视图复现相同注册表语义。

## 7. v0.9.0：多章节内容包

### 目标

在原点到首个三维领域之后增加下一段可玩规则，同时保证 v0.1–v0.8 存档可读取。

### 交付项

- 选择下一章节并记录原典来源、改编边界和玩法目标；
- 为内容包增加阶段间依赖与显式迁移，不覆盖 `origin.json` 的既有语义；
- 浏览器增加对应的 3D 场景状态、叙事消息和行为反馈；
- Luanti 增加领域节点、交互和存档迁移；
- 增加从旧存档进入新章节及回退读取的测试夹具。

具体维度、数值和故事节点必须先形成独立设计稿，再进入 schema；本路线图不提前把“32 维”硬编码为线性关卡。

## 8. v1.0.0：稳定互操作基线

v1.0 不是内容完成版，而是工程兼容承诺。发布前至少满足：

- 浏览器与 Luanti 两个平台完成持久断线、重复、乱序和权限测试；
- ESIP 核心消息拥有稳定版本策略、兼容矩阵和弃用周期；
- 存档、身份、时间线和传输层都有备份、迁移和恢复文档；
- 发布资产可复现，安全扫描和真实运行时测试稳定；
- 至少一个受限外部适配器能够接入且不能越过状态权威；
- 运维者能够查看健康状态、积压、租约、失败和保留期，而不暴露令牌或玩家名。

## 9. 持续工作流

以下工作贯穿每个版本，不单独阻塞主线：

- 改善 WebGL 动画、消息板、移动端布局和低性能设备降级；
- 补充中文界面文案、键盘操作、屏幕阅读器语义和减少动态效果；
- 控制浏览器存储、消息历史、时间线和日志的容量；
- 维护 Windows、Linux、官方 Luanti 便携包和 Mineclonia 兼容性；
- 清理弃用 API、依赖漏洞和公开树中的部署文件风险；
- 在 README、CHANGELOG、协议和接入指南中同步每次语义变化。

## 10. 暂不进入范围

以下方向保留研究，但在前置版本完成前不进入主线：

- 直接复制或跨服迁移完整 Luanti 世界数据库；
- 公网暴露当前 Bearer sidecar；
- 无权威确认的跨游戏资产交易；
- AI 直接执行 Lua、shell、SQL 或写玩家 metadata；
- 真实货币经济、开放式玩家交易和不可逆资产铸造；
- 把 32 维、平行宇宙和多服务器一次性实现为单个大版本；
- 在源码仓库提交真实世界、日志、令牌、模型权重或玩家数据库。

## 11. 下一迭代建议

世界观察与有限实验的最小纵切已经完成：

1. 已定义只读公共外壳：`universeId`、`timelineId`、`domain`、`tick`、`timeScale`、`revision`、`phase`、`rulePackVersion`、`summary`、`recentEvents`、`capabilities` 和 `provenance`；
2. 已为原点、恒星和文明分别增加观察适配器，不改变各自算法和权威写入口；
3. 已增加公共观察验证器，拒绝未知字段、不明来源和缺少版本的快照；
4. 已建立只读世界注册表测试，证明同一个观察器能够列出、查询和比较三个领域；
5. 已以 Babylon 文明观测台作为第一个应用层消费者，展示自动演化、时间控制、事件流和只读分支对比；
6. 已定义有限 Rule Patch 和 `WorldExperimentProposal`，提案绑定源 revision、tick 与 history hash，二次确认后才建立带可验证 causality 的差异分支；
7. 已让 openVirFactory 把自然语言转换为保持 `pending` 的严格提案，并复用相同确认路径；模型不能设置权威来源字段，也不具有 controller 写权限；
8. 已为文明 controller 增加 sidecar 记录恢复、稳定时间槽 ID、调度租约和 crash-safe pulse；租约前后中断与确认丢失均有自动测试；
9. 已定义正式实验 review/commit 消息，强制 source/actor/universe 授权、请求过期、提交点重校验和跨 runtime 重启幂等；
10. 下一切片实现同源身份网关，并完成真实 provider 往返、速率限制和故障诊断验收。

这一顺序先用真实领域纵切寻找共同抽象，避免过早创造一个无法承载现有状态的“万能”基类。渲染优化可以并行进行，但只能消费已确认观察和事件，不能建立第二套权威指标。
